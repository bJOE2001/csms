# Coffee POS visual direction

The supplied coffee-shop POS reference guides the white surfaces, coral accents, charcoal text, compact navigation, horizontal product cards and separate order pane. The application has five business screens: POS, Menu, Sales, Expenses and Libraries. Expenses reuses Menu's compact overview cards, integrated table toolbar and dialog controls. The presentation mockup's decorative outer canvas is deliberately omitted.

## Shared styling

- `src/app/tokens.css` owns semantic HSL colors consumed by Tailwind/shadcn and CSS aliases. Coral primary buttons use dark text; an accessible burnt-coral accent is used for prices, active navigation and focus indicators. White surfaces sit on a neutral gray workspace with no outer canvas or frame. The tokens also own spacing, motion, radii and core panel/media dimensions: 216px sidebar, 340–420px order pane, 1120px maximum menu content, and 64 × 64px POS product media.
- Typography uses self-hosted Manrope variable weights, tabular monetary figures and consistent heading weights. The original font and complete SIL Open Font License are in `public/fonts/manrope/`, sourced from [Google Fonts](https://github.com/google/fonts/tree/main/ofl/manrope). No external font service runs in the application. Lucide React supplies a consistent icon family through the existing `Icon` API.
- `workspace-shell.css` owns the full-viewport application, sidebar and POS menu/cart arrangement. Desktop at 1280px and above uses a 100dvh grid with no external margins, maximum width or rounded container corners. The sidebar remains at the left; the menu scrolls independently in the center; order items scroll above the visible checkout controls at the right. On shorter desktop screens, the entire order pane scrolls to keep its contents reachable. From 768px through 1279px, every module uses the shared two-row header: branding and Sign out first, then one horizontal navigation row. Navigation scrolls horizontally when needed; it never wraps at tablet widths. Below 768px, the shared compact navigation can wrap. Below 1280px, the product menu fills the workspace, and the always-visible Cart button opens a right-side Radix Dialog drawer. The same cart and checkout markup uses the existing workspace state in either layout; dismissing or resizing does not reset selections, cash or pending checkout. Drawer focus is trapped and restored to its trigger, with Escape, backdrop and close-button dismissal. Its item list scrolls above the checkout controls; short landscape screens scroll the whole drawer to keep every control reachable. Below 768px the product grid has one column; larger layouts still use the actual menu container width to choose columns. Section borders and internal component padding remain intact.
- `workspace.css` owns shared cards, summary metrics and dialog layouts. `tables.css` owns management table column roles, typography, spacing, responsive records, empty states and icon actions. `receipt.css` preserves the separate customer print layout. `globals.css` owns controls, account layouts, focus and reduced-motion behavior.
- `Select` in `src/components/ui/select.tsx` wraps Radix Select for Menu filters and product categories. `select.css` owns 44px standard and 40px compact triggers (44px on mobile), white portaled menus, soft coral highlights, selected checkmarks and scroll controls. Popup dimensions use Radix collision and available-height variables; focus uses the shared single-stroke tokens. Pass original string values through `options`, `value`/`defaultValue` and `onValueChange`. Named fields submit those same values, including an empty category; cancelled form resets retain drafts. Sales and Expenses currently have no select controls.
- `ProductCard` composes the thumbnail, inline name/price, availability and conditional cart actions. Management actions live exclusively in Menu. Sized products use labeled native radio groups styled as inline coral size pills; selection updates the displayed price and Add to cart action. Up to six sizes wrap naturally, while larger sets scroll horizontally with keyboard focus. Regular products add directly through the same action. An unselected cart line shows one outlined coral Add to cart button. Once added, the card shows a noninteractive filled Added to cart status with a subtle quantity indicator for the selected size. Quantity controls and removal live exclusively in the Cart panel or drawer. Decreasing to zero or deleting the line restores Add to cart; card indicators derive directly from the same cart snapshots. Controls wrap within the footer when needed, retaining 44px targets. Cards use content-driven heights, 12px padding and 8px internal gaps without a fixed or minimum height. A two-column grid becomes one column when the menu panel is narrow.
- Product thumbnails use a neutral image icon and name initials. Images and descriptions come from Menu records, while category records are maintained in Libraries; none are invented. Real category pills and name search filter POS products. Availability filtering, sorting and editing belong to the Menu management table. Test screenshots use a demonstration catalog; no demonstration products are written to the shop.
- Checkout uses compact thumbnail rows, circular quantity controls, an immediate Trash2 removal action per cart line, a charcoal selected payment method and a coral Place an order action. The button retains the existing transaction completion flow; saved-sale retries retain their distinct label and behavior. The header, empty state and summary retain a clear hierarchy without the former duplicate page headings or large card action rows. Shared shadcn button variants now use the same pill radius as the reference.

## Usability and compatibility

Size pills, quantity controls and cart removal controls have minimum 44px touch targets. Menu form controls and primary actions retain 44px targets. Keyboard users can skip the navigation, and active links include an indicator and `aria-current`. Search and availability filters include explicit empty feedback and a reset action. Dialog focus, dirty-form protection, pending states, reduced-motion behavior and notifications remain in the existing shared components.

Measured contrast for principal pairs: button text on coral 7.4:1, brand accent on white 5.21:1, brand accent on the pale selected-navigation surface 4.68:1, muted text on the workspace 5.38:1, and input boundaries on white 3.04:1. These measurements cover the listed pairs, not a complete accessibility certification.

The redesign changes presentation and component composition. Checkout payloads, server price/cost validation, saved-sale IDs, cash/GCash flows, product availability, profit calculations, receipts/refunds, expenses, date filtering and CSV exports retain their existing behavior. The Menu enhancement adds optional catalog fields and checkout size identifiers through the existing endpoint. The schema-first migration and compatibility details are documented in `MENU_MANAGEMENT.md`.

Menu Management uses a compact four-metric overview, a searchable product table with category/availability/sort controls, with category maintenance in Libraries. At mobile widths, the same product table reflows into labeled rows with all fields and actions retained. Product dialogs use two-column basic fields on desktop and a single column on mobile; custom size rows retain explicit labels, default selection, availability and inline errors. Keyboard focus, pending states, confirmation and dirty-form protection use the shared Radix-based dialog workflow.

Management tables use the shared `DataTable` column `kind`: `primary` consumes remaining width, `text` wraps longer category/size content within a readable measure, and `compact`, `status` and `actions` fit their contents. `numeric` aligns headers and values to the right with tabular figures. Width rules apply from 768px; below that, the same semantic table becomes labeled stacked records with full-width primary information and right-aligned actions. Overflow stays inside the focusable table region, with a scroll hint only when necessary. Sorting, record counts and search remain in `DataTable`; no pagination has been added.

`TableActionButton` uses Lucide Pencil, Trash2 and Eye icons for existing product, category, expense and receipt actions. Buttons are 40px on desktop and 44px below 1280px or with a coarse pointer, with 18px icons and 8px group spacing. A single coral keyboard outline, neutral default appearance, coral ordinary hover and red destructive hover use existing tokens. Radix Tooltip supplies portaled, collision-aware hover/focus labels and Escape dismissal; native buttons retain descriptive `aria-label` names and disabled semantics. `FormDialog.tableAction` changes only the trigger presentation, preserving confirmation, protected category deletion, focus restoration, dirty drafts and pending behavior. Sales keeps the readable receipt number alongside a dedicated Eye action; printing, refunding and cost recording remain inside the receipt dialog.
