# Coffee POS visual direction

The supplied coffee-shop POS reference guides the white surfaces, coral accents, charcoal text, compact navigation, horizontal product cards and separate order pane. The application has four business screens: POS, Menu, Sales and Expenses. Expenses reuses Menu's compact overview cards, integrated table toolbar and dialog controls. The presentation mockup's decorative outer canvas is deliberately omitted.

## Shared styling

- `src/app/tokens.css` owns semantic HSL colors consumed by Tailwind/shadcn and CSS aliases. Coral primary buttons use dark text; an accessible burnt-coral accent is used for prices, active navigation and focus indicators. White surfaces sit on a neutral gray workspace with no outer canvas or frame. The tokens also own spacing, motion, radii and core panel/media dimensions: 216px sidebar, 340–420px order pane, 1120px maximum menu content, and 92 × 120px product media.
- Typography uses self-hosted Manrope variable weights, tabular monetary figures and consistent heading weights. The original font and complete SIL Open Font License are in `public/fonts/manrope/`, sourced from [Google Fonts](https://github.com/google/fonts/tree/main/ofl/manrope). No external font service runs in the application. Lucide React supplies a consistent icon family through the existing `Icon` API.
- `workspace-shell.css` owns the full-viewport application, sidebar and POS menu/cart arrangement. Desktop uses a 100dvh grid with no external margins, maximum width or rounded container corners. The sidebar remains at the left; the menu scrolls independently in the center; order items scroll above the visible checkout controls at the right. On shorter desktop screens, the entire order pane scrolls to keep its contents reachable. Below 1000px navigation moves above the content; below 760px the menu and cart return to normal document flow, with a sticky View order shortcut. Section borders and internal component padding remain intact.
- `workspace.css` owns shared cards, summary metrics, tables and dialog layouts. `receipt.css` preserves the separate customer print layout. `globals.css` owns controls, account layouts, focus and reduced-motion behavior.
- `ProductCard` composes the thumbnail, inline name/price, availability, order count and compact add affordance. Management actions live exclusively in Menu. Sized products use a compact, labeled size selector, and the add action uses the selected price. Regular products add directly through the same action. Cards start at 176px tall and grow when their real content requires it. A two-column grid becomes one column when the menu panel is narrow.
- Product thumbnails use a neutral image icon and name initials. Images, descriptions and categories now come from Menu records; none are invented. Real category pills and name search filter POS products. Availability filtering, sorting and editing belong to the Menu management table. Test screenshots use a demonstration catalog; no demonstration products are written to the shop.
- Checkout uses compact thumbnail rows, circular quantity controls, a charcoal selected payment method and coral completion action. The header, empty state and summary retain a clear hierarchy without the former duplicate page headings or large card action rows. Shared shadcn button variants now use the same pill radius as the reference.

## Usability and compatibility

Quantity controls are 40px on desktop and 44px on mobile. Menu form controls and primary actions retain 44px targets. Keyboard users can skip the navigation, and active links include an indicator and `aria-current`. Search and availability filters include explicit empty feedback and a reset action. Dialog focus, dirty-form protection, pending states, reduced-motion behavior and notifications remain in the existing shared components.

Measured contrast for principal pairs: button text on coral 7.4:1, brand accent on white 5.21:1, brand accent on the pale selected-navigation surface 4.68:1, muted text on the workspace 5.38:1, and input boundaries on white 3.04:1. These measurements cover the listed pairs, not a complete accessibility certification.

The redesign changes presentation and component composition. Checkout payloads, server price/cost validation, saved-sale IDs, cash/GCash flows, product availability, profit calculations, receipts/refunds, expenses, date filtering and CSV exports retain their existing behavior. The Menu enhancement adds optional catalog fields and checkout size identifiers through the existing endpoint. The schema-first migration and compatibility details are documented in `MENU_MANAGEMENT.md`.

Menu Management uses a compact four-metric overview, a searchable product table with category/availability/sort controls, and category rows. At mobile widths, the same product table reflows into labeled rows with all fields and actions retained. Product dialogs use two-column basic fields on desktop and a single column on mobile; custom size rows retain explicit labels, default selection, availability and inline errors. Keyboard focus, pending states, confirmation and dirty-form protection use the shared Radix-based dialog workflow.
